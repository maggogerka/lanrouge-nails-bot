# Рассылки

## Безопасный запуск

Рассылки по умолчанию выключены. После миграции и smoke test администратор включает их в
настройках, открывает `/admin` → «📢 Рассылки», создаёт текст/фото/альбом, аудиторию и CTA,
проверяет preview и оценку числа получателей, делает test-send и только затем явно
подтверждает немедленный или запланированный запуск.

Поддерживаются подписанные клиенты, наличие завершённого визита, отсутствие будущей
записи, неактивность N дней, CRM-тег и история услуги. Test-send отправляется только
авторизованному администратору и не создаёт массовую очередь.

## Consent и snapshot

При подтверждении выбранные user IDs один раз фиксируются в `broadcast_recipients`.
Изменение сегмента позже не расширяет кампанию. Перед каждой отправкой worker снова
проверяет marketing consent, opt-out и блокировку чата. Пользователь без действующего
согласия получает terminal `unsubscribed`, заблокировавший бота — `blocked`.

## Доставка

Отдельный `broadcast-worker` захватывает due recipients через `FOR UPDATE SKIP LOCKED`,
использует lease, ограничение сообщений в секунду, `RetryAfter`, backoff и terminal
statuses. Уже `sent` не отправляются повторно обычным циклом. Отмена переводит оставшиеся
pending/retry/processing в `skipped`. Статистика содержит sent/failed/skipped/blocked,
но не заявляет недоступные Bot API «открытия». Внутренние callback-клики фиксируются без
внешнего tracking URL.

Текст клиента отправляется с `parse_mode=None`; HTML-инъекция не интерпретируется.
Основные модули: `app/services/broadcast_service.py`,
`app/services/broadcast_delivery_service.py`, `app/workers/broadcasts.py`.
