# Retention фото-референсов v0.3.1

## Что хранится

Оригиналы фотографий остаются в Telegram. Приложение хранит в PostgreSQL только
`file_id`, `file_unique_id` и минимальные метаданные связи с записью. В Docker Compose
нет volume для фотографий, код не скачивает их на VPS и не создаёт временные файлы.
Поэтому очистка освобождает идентификаторы и доступ приложения, а не место, занятое
оригиналом на серверах Telegram.

Отдельные `local_path` и `storage_kind` не добавлены: в поддерживаемой архитектуре
существует только Telegram-hosted storage. FK `RESTRICT` не позволяет удалить
Appointment и оставить потерянные reference rows.

Черновик бронирования хранится в Redis FSM не более
`REFERENCE_DRAFT_RETENTION_HOURS` (24 часа по умолчанию). После подтверждения каждая
строка получает UTC timestamp `expires_at`.

## Сроки по умолчанию

| Состояние записи | Начало срока | Срок |
|---|---|---:|
| `completed` | `completed_at`, иначе плановое окончание | 30 дней |
| `cancelled_by_client` / `cancelled_by_admin` | `cancelled_at`, иначе плановое окончание | 7 дней |
| `no_show` | плановое окончание | 14 дней |
| будущая активная запись | плановое окончание | не удаляется до визита |
| просроченная активная запись | плановое окончание | не более 30 дней |

При создании, переносе, завершении, отмене и отметке неявки срок пересчитывается.
При переносе активные референсы переходят к новой Appointment. Повторный запуск
очистки безопасен: уже обезличенные строки пропускаются.

Настройки окружения:

```dotenv
REFERENCE_COMPLETED_RETENTION_DAYS=30
REFERENCE_CANCELLED_RETENTION_DAYS=7
REFERENCE_NO_SHOW_RETENTION_DAYS=14
REFERENCE_DRAFT_RETENTION_HOURS=24
REFERENCE_CLEANUP_INTERVAL_HOURS=6
```

## Автоматическая и ручная очистка

`reference-cleanup-worker` запускает цикл каждые 6 часов. Каждый кандидат очищается
в отдельной транзакции: ошибка одной строки не останавливает остальные. Удаляются
`file_id` и `file_unique_id`, выставляется `deleted_at`; сама запись Appointment не
удаляется.

Администратор может выполнить то же действие из карточки записи после отдельного
подтверждения. Клиент может удалить собственные референсы из своей карточки. После
этого бот не сможет повторно запросить фотографии по сохранённым ID. Telegram Bot API
не даёт боту гарантии удаления исходного файла с инфраструктуры Telegram.

Разовый предварительный просмотр и запуск:

```powershell
docker compose run --rm bot python -m app.maintenance.cleanup_references --dry-run
docker compose run --rm bot python -m app.maintenance.cleanup_references --execute
```

Вывод содержит только количество проверенных/очищенных строк, оценку освобождённых
байтов идентификаторов, число ошибок и длительность — без Telegram ID и PII.

## Наблюдаемость

Worker пишет структурированную сводку каждого цикла и предупреждает, если:

- успешной очистки не было более 24 часов;
- накопилось три и более неудачных цикла;
- свободное место текущего filesystem ниже 15%.

Compose ограничивает json-логи каждого контейнера тремя файлами по 10 МБ.
Состояние последнего цикла хранится в singleton-строке `reference_cleanup_state`,
без накопления неограниченного maintenance-журнала.
