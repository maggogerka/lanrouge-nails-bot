# Администрирование отзывов v0.3.0

## Feature flag

При `reviews_enabled=false`:

- клиентские и административные кнопки отзывов скрыты;
- новые отзывы не принимаются;
- review request jobs не создаются;
- уже ожидающие review jobs отменяются либо безопасно завершаются worker без отправки;
- существующие отзывы и ревизии сохраняются.

## Редактирование

Администратор может изменить rating, text и moderation status. В одной транзакции сначала создаётся `ReviewRevision` со старыми значениями и actor ID, затем обновляется Review и AuditLog. Полный текст не попадает в структурированные логи или AuditLog diff.

Редактирование не создаёт клиентское согласие на публикацию. Approved/public выдача по-прежнему требует исходный `publication_consent=true`, отсутствие `deleted_at` и включённые отзывы.

## Удаление и восстановление

Обычное удаление является soft delete: заполняются `deleted_at`, `deleted_by_user_id`, `deletion_reason`, отзыв скрывается из публичной выдачи и статистики. Восстановление очищает поля удаления и возвращает отзыв в `pending`, если прежняя публикационная корректность не может быть доказана.

Физическое удаление доступно только администратору после отдельного подтверждения. Оно не каскадирует Appointment/User/AuditLog. Ревизии удаляются или анонимизируются по документированной retention-политике в той же транзакции.

## Права

Admin handler и service оба проверяют актуальный Telegram ID. Клиент может создать отзыв только для собственной завершённой записи и не может вызывать административное изменение по подставленному callback ID.
